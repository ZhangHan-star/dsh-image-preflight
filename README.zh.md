# 图片预检

> 整个项目——插件代码、测试、文档——都是用 DeepSeek 写的。

这是一个 DSH 插件。它只干一件事：在你发图片之前先把图检查一遍，能修好的修好，再交给 DSH 保存。

修不好的，它会原样放过去——所以你看到的报错和没装插件时一模一样。

## 你大概见过这种情况

拖进去一张图，DSH 弹一句：

> 仅支持 PNG、JPG、WebP、GIF 格式的图片

可那张图明明就是 PNG，双击能打开，相册里看也正常。换一张图就好了，换回这张又不行。

## 为什么会这样

浏览器判断图片是什么格式，看的是文件名后缀，不看内容。后缀是 `.png`，它就告诉 DSH「这是 PNG」。

DSH 不太信这个说法，自己把文件拆开看，发现里头其实是张 JPEG。两边对不上，于是拒收——还给了上面那句让人摸不着头脑的提示。

最容易踩这个坑的来源：淘宝闲鱼保存的图、微信转发的图、网页右键另存、手机截图被改过名。这些图多半是从别处转出来的，后缀早就和内容对不上了。

## 它到底做了什么

- **后缀在撒谎的**：只改「类型」这个标签，图片本身一个字节都不动，画质没有任何损失。
- **格式 DSH 本来就不认的**（AVIF、TIFF、SVG 之类）：转成 JPEG；图有透明背景就转成 WebP，透明会保住。
- **太大、太宽的**：超过 DSH 的限制就等比缩小，实在压不下来再降一点质量，缩到刚好能收下为止。
- **写法不规范的**：`image/jpg`、`image/x-png` 这种也认。

判断标准不是写死的，每次都去读 DSH 当前的限制。你在 DSH 里把上限调大调小，它跟着变。

## 它不会做什么

- **文件真的坏了**（下载到一半、0 字节、把 txt 改名成 png）：修不了，照旧报错。它不会为了让上传"成功"而硬塞一张坏图进去。
- **一次拖 25 张**：超过数量上限就是超过，它不会偷偷删掉你的图来凑数。
- **真正的 .avif / .heic，或者没有后缀的文件**：浏览器那一关就拦下了，根本到不了它这一步。
- **模型不支持看图**：那是模型的事，和附件没关系。

## 安装

1. 打开 DSH 的插件管理器（左侧 Plugins）。
2. 选「从本地目录安装」，指到这个文件夹。
3. 重启 DSH。

装好之后插件列表里会多一个「图片预检」。想确认真的生效，拖一张以前发不出去的图试试就行。

习惯命令行的话：

```
dsh plugin --profile desktop add dsh-image-preflight
```

## 想改设置的话

默认值基本够用。真要改，写在插件配置的 `config` 下面：

```yaml
- id: dsh-image-preflight
  name: dsh-image-preflight
  config:
    logLevel: debug
```

最常动的两个：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `logLevel` | `info` | 改成 `silent` 就不打日志了，`debug` 能看到每一次编码尝试 |
| `animated` | `shrink` | 超限的动图怎么处理：`shrink` 保留每一帧，`first-frame` 只留第一帧，`passthrough` 干脆不动 |

剩下那些（各种上限覆盖、输出格式、质量阶梯、并发、超时）都在 `lib/config.js` 里，也都有默认值。

## 日志

每修一张图打一行。不打印图片内容，也不打印你的目录路径：

```
[image-preflight] 1793029414251.png: 872x1920 574.2 KB image/png -> 872x1920 574.2 KB image/jpeg [relabel: declared image/png but bytes are image/jpeg; 0ms]
```

## 几个你可能想问的

**会不会把我的图改坏？**
只会往「能发出去」的方向改。改标签的时候不动字节；真要重编码，也只在你超过限制的时候。本来就合规的图，从它手里原样过去。

**会不会偷偷把图传出去？**
不会。全程在本机内存里处理，不联网，也不写临时文件。

**要不要额外装什么？**
依赖 sharp。万一 DSH 里没有，插件会安静地什么都不做，上传行为和没装一样，不会报错也不会卡住。

**会不会影响聊天界面？**
不会。它只在服务端接图片的那一刻动手，界面、缩略图、草稿条、历史记录都还是 DSH 原本的样子。
